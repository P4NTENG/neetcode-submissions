# 전화번호 목록 문제 풀이 과정

## 아이디어 진화 과정

### 1. 자신을 포함하지 않는 리스트를 생성 → 순회하면서 목표를 찾기

**세부 구현법**

리스트 인덱스 슬라이싱을 이용해 현재 전화번호를 제외한 리스트를 생성한다.

```python
exclude_list = phone_book[:index] + phone_book[index+1:]
```

이후 `exclude_list`를 순회하면서 현재 전화번호가 다른 전화번호의 prefix인지 확인한다.

**Prefix 비교 방법**

직접 슬라이싱하여 비교할 수 있다.

```python
phone_number[:len(target_number)] == target_number
```

또는 문자열 메소드인 `startswith()`를 사용할 수 있다.

```python
phone_number.startswith(target_number)
```

하지만 모든 전화번호에 대해 다른 전화번호와 비교해야 하기 때문에 **이중 for문을 사용하면 시간복잡도가 O(N²)** 이 되어 시간 초과가 발생할 수 있다.

---

### 2. 전화번호를 정렬하면 더 효율적으로 비교할 수 있지 않을까?

여기서 다음과 같은 사실을 알 수 있다.

> **긴 문자열은 짧은 문자열의 prefix가 될 수 없다.**

따라서 `phone_book`을 길이순으로 정렬하면 짧은 전화번호부터 비교할 수 있다.

하지만 정렬 자체에도 오버헤드가 발생한다.

→ Python의 정렬 알고리즘인 **Timsort**에 대해 알아봄
→ 사전식 정렬을 이용하면 더 효율적으로 문제를 해결할 수 있다는 것을 알게 됨

---

### 3. 사전식 정렬을 이용하면 인접한 전화번호만 비교하면 된다

Python에서는 문자열을 기본적으로 사전식으로 비교하기 때문에 `sort()`를 사용하면 사전식으로 정렬된다.

```python
phone_book.sort()
```

정렬된 상태에서는 prefix 관계에 있는 문자열이 서로 가까운 위치에 오기 때문에 **인접한 전화번호만 비교하면 된다.**

```python
for p1, p2 in zip(phone_book, phone_book[1:]):
    if p2.startswith(p1):
        return False
```

정렬에 `O(N log N)`, 이후 순회에 `O(N)`이 걸리므로 전체 시간복잡도는 **O(N log N)** 이다.

## Hash를 이용한 접근

### 문제를 반대로 정의하기

정렬을 이용하면 `O(N log N)`이 필요하다.

그렇다면 문제를 다른 방향에서 생각해볼 수 있다.

기존에는:

> **특정 전화번호가 어떤 번호의 일부분인가?**

를 확인하려고 했다.

이를 반대로 생각하면:

> **어떤 전화번호의 일부가 이미 등록되어 있는가?**

가 된다.

즉, 현재 전화번호의 prefix를 하나씩 만들어보면서 해당 prefix가 이미 `set`에 등록되어 있는지를 확인하는 것이다.

```text
1195524421
↓
1
11
119
1195
11955
...
```

이 중 `119`가 이미 `set`에 존재한다면 `1195524421`은 등록된 전화번호의 prefix가 된다.

Python에서 `set`은 Hash Table을 기반으로 구현되어 있으므로 특정 값의 존재 여부를 평균적으로 **O(1)** 에 확인할 수 있다.

---

## 핵심 아이디어

이 문제에서 중요한 것은 **문제를 거꾸로 정의하는 것**이다.

기존 접근:

```text
A가 B의 prefix인가?
```

문제를 뒤집으면:

```text
B의 prefix 중 A가 존재하는가?
```

가 된다.

이처럼 문제의 방향을 반대로 생각하면 Hash 자료구조를 활용할 수 있다.

> **"무엇이 나를 포함하는가?"**
>
> ↓
>
> **"내가 포함하는 것 중 이미 존재하는 것이 있는가?"**

이런 방식은 Hash를 사용하는 문제에서 자주 등장하는 패턴이다.

## 발전 과제

### 굳이 Hash 함수를 이용하려고 `set`을 써야 하나?

그럴 필요는 없다.

Python의 `__hash__` 매직 메서드를 이용하면 직접 Hash 함수를 지정할 수도 있다.

하지만 그렇게 하려면 커스텀 클래스가 필요하고, 오히려 이것 자체가 병목이 되어 성능상의 손해가 발생할 수 있다.

결국 특별한 비즈니스 규칙이 필요한 것이 아니라면 **Python의 내장 `set`을 사용하는 것이 성능과 구현 측면에서 유리하다.**

Python의 내장 자료구조는 C 레벨에서 최적화되어 있기 때문이다.

---

### Timsort가 뭐임?

Python의 기본 정렬 알고리즘은 **Timsort**이다.

Timsort는 **Insertion Sort와 Merge Sort를 결합한 정렬 알고리즘**이다.

정렬의 최소 단위인 **Run**을 만들고, 이를 기준으로 병합 정렬을 수행한다.

* 최악의 경우 시간복잡도: `O(N log N)`
* 이미 정렬되어 있거나 부분적으로 정렬된 데이터에서 효율적
* Python의 `list.sort()`와 `sorted()`에서 사용

또한 Python의 문자열 데이터는 비교할 때 기본적으로 **사전식으로 비교**된다.

```python
"119" < "123"
# True
```

따라서 별도의 `key`를 지정하지 않으면 문자열 자체의 사전식 순서로 정렬된다.

```python
phone_book.sort()
```

정렬 기준을 변경하고 싶다면 `key`를 사용할 수도 있다.

```python
phone_book.sort(key=len)
```
